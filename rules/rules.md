# 前哨：规则与协议（A 阶段开发草稿）

规则集：`standard-1` 起点；引擎：`0.1.0-dev`；协议：HRW 1。

**当前实现只有引擎和消息解析。** 运行器、SDK、命令行、公开地图集和对手尚未交付，以下运行限制是既定要求，不代表已完成验证。实现细节及待确认项见 `docs/IMPLEMENTATION_NOTES.md`；规则测试索引见 `tests/COVERAGE.md`。

## 1. 棋盘与目标

两人完全信息、同时行动。地图宽、高各为 24–40，关于中心旋转 180° 对称，两座基地互为对称点。坐标 `(x,y)` 从左上角 `(0,0)` 开始，向右、向下递增。距离统一为 `|dx| + |dy|`，相邻只包括上下左右。

| 地形 | 含义 | 单位能否进入 |
|---|---|---|
| `.` | 空地 | 能，最终每格至多一个单位 |
| `#` | 墙 | 不能 |
| `O` | 矿 | 不能，采完仍是矿格 |
| `S` | 塔基 | 不能，建塔后也不能 |
| `0`、`1` | 两方基地 | 不能 |

攻击阶段一方基地被摧毁，该方立即输；双方同回合被摧毁则平局。否则第 300 回合结算完后依次比较：塔累计分、累计卸货量、基地生命。前一项相同才比较下一项，全部相同则平局。基地生命不回复。单位死亡后携带的矿消失，不能拾取。

## 2. 实体和全部规则参数

| 实体 | 造价 | 生命上限 | 相邻攻击伤害 |
|---|---:|---:|---:|
| 工兵 W | 50 | 40 | 5 |
| 战士 S | 100 | 100 | 20 |
| 基地 | — | 1000 | 使用 FIRE，伤害 10、射程 2 |
| 塔 | 150 | 300 | 无攻击 |

工兵每回合最多采 10，最多携带 60；只有工兵能采矿、卸货和建塔。塔建在空塔基上，每回合贡献 1 分，同时是卸货点。塔被摧毁后留下空塔基，不能占领敌塔。

每方开局基地满血、能量 300、2 个满血工兵，初始站位两方对称。工兵和战士合计至多 40。基地每回合最多生产一个单位，生产位置距基地不超过 2；距己方基地不超过 2 的己方单位，每回合回复 5 生命，不超过上限。

协议会发送下列全部参数，bot 应读取而非把数值写死：

```text
TURNS 300              START_ENERGY 300       START_WORKERS 2
POP_CAP 40             BASE_HP 1000           BASE_FIRE_DMG 10
BASE_FIRE_RANGE 2      SPAWN_RANGE 2          REGEN_HP 5
REGEN_RANGE 2          WORKER_COST 50         WORKER_HP 40
WORKER_DMG 5           MINE_RATE 10           CARRY_MAX 60
SOLDIER_COST 100       SOLDIER_HP 100         SOLDIER_DMG 20
TOWER_COST 150         TOWER_HP 300           TOWER_POINTS 1
```

单位 ID 全局唯一、不复用。当前分配方式为各方独立序号乘玩家数再加玩家号；同一方内部按 ID 排建造先后。初始位置先选离基地最近的空地，同距采用双方互为旋转的局部排序。bot 以 `UNIT` 消息中的实际 ID 和坐标为准。

## 3. 指令与结算

每个单位每回合最多一条指令；基地可各发一条 SPAWN 和 FIRE。未收到指令的单位原地不动，没有自动攻击或自动射击。

| 指令 | 回合开始时必须满足 |
|---|---|
| `MOVE id N/E/S/W` | 己方存活单位，方向为北/东/南/西之一；目的格能否进入在移动阶段判断 |
| `ATTACK id x y` | 目标为相邻敌方单位、塔或基地 |
| `MINE id x y` | 工兵与有余矿的矿格相邻，携带量未满 |
| `BUILD id x y` | 工兵与空塔基相邻；能量到建造阶段才检查 |
| `SPAWN W/S x y` | 位置是无人占据的空地、距己方基地至多 2，人口未满、能量足够 |
| `FIRE x y` | 目标为距己方基地至多 2 的敌方单位，不能射塔或基地 |

先用共同的回合开始局面校验，再按下列顺序结算。除明确规定的同方建造顺序外，同一步内同时生效。

1. **校验**：非法行只记警告，不判负。第一条语法完整、指向己方存活单位的指令占用该单位槽，即使目标不合法也不能用后一条补上；语法错误的行不占槽。基地两个槽分别处理。
2. **攻击**：ATTACK、FIRE 按回合开始的位置命中；即使目标准备移动也会先受伤。所有伤害同时生效，死亡单位的攻击仍生效，其他动作取消。移除死亡单位和塔；若基地死亡，立即结束，不再生产、卸货、回复或计分。
3. **生产**：成功才扣款；双方在同一格生产都失败且不扣款。开始时已被占用的位置，即使占据者在攻击阶段死亡，也不能用于这次生产。开始时人口已满，不能利用本回合阵亡腾出的人口。
4. **移动**：先拒绝非空地或越界的目的格；再使所有争同一目的格的移动失败；再使直接互换位置的两个单位失败。反复使“目标格仍有不动单位”的移动失败，直到不再变化。其余全部成功，允许三个以上单位的轮转。新生产的单位已占格，算不动单位。
5. **采矿**：每个存活工兵的需求 `q=min(10,60-携带量)`。同一矿格总需求不超过储量时各得 q；否则各得 `min(q,储量//人数)`，剩余全部作废，矿量归零，不重新分配零头或受携带上限限制的份额。
6. **卸货**：与己方基地或现存己方塔相邻的工兵自动卸下全部携带量，增加能量和累计卸货量。同一工兵即使邻接多个卸货点，也只卸一次。
7. **建造**：允许用刚卸货的能量。双方争同一塔基都失败、不扣款，冲突判断先于支付能力。己方多个存活工兵争同一塔基，ID 最小者执行；同方其他塔基的建造也按工兵 ID 递增扣款，缺钱的失败。新塔本回合尚不能接收卸货。
8. **回复**：按移动后的坐标回复己方基地附近的存活单位；不会救活已死亡单位，塔不会回复。
9. **计分**：每座现存己方塔加 1 分，包括本回合新建的塔。然后检查回合上限。

移动受阻、建造争抢或缺钱等不导致判负，当前通过 INVALID 事件告知本方并计入警告。上述边界处理尚待 A 阶段审查确认。

## 4. bot 协议

每局启动一个长期运行进程，通过标准输入和标准输出交换 UTF-8 文本行，行尾为 `\n`。每条消息以 `END` 结束。标准输出只写协议，调试信息写标准错误。bot 可以跳过不认识的输入关键字，以兼容以后新增字段。

### 初始化

```text
HRW 1
RULESET standard-1
YOU 0
SEED 8273645512
PARAM TURNS 300
PARAM START_ENERGY 300
...其余全部参数，每行 PARAM 名称 数值...
LIMIT TURN_CPU_MS 100
LIMIT INIT_CPU_MS 2000
LIMIT BANK_MS 3000
MAP 32 32
...32 行地图，每行 32 个字符...
ORE 5 7 400
...全部矿格和初始储量...
END
```

省略号是说明，不是实际协议行。初始化时限内回复 `READY` 并刷新输出。SEED 是提供给本方 bot 的随机种子，引擎结算不使用随机数。

### 每回合观察

首次为 `TURN 1`。双方的能量、单位、建筑和矿量都可见。

```text
TURN 17
PLAYER 0 <能量> <塔累计分> <基地生命> <累计卸货量>
PLAYER 1 <能量> <塔累计分> <基地生命> <累计卸货量>
UNIT <id> <所属方> <W或S> <x> <y> <生命> <携带量>
TOWER <x> <y> <所属方> <生命>
ORE <x> <y> <余量>
EVENT <类型> <字段...>
BANK <剩余储备毫秒>
END
```

每个存活单位、塔各一行，矿只列余量大于 0 的格子。事件来自上一回合；本方 INVALID 只发给本方。回复零条或多条指令，最后写 `END` 并刷新输出，例如：

```text
MOVE 12 N
MINE 3 6 7
SPAWN S 4 5
END
```

### 容错

逐行校验。未知指令、字段错误、不存在或非己方的单位、不满足条件的操作，只作废对应行。允许空行、首尾空白、制表符和 CRLF。单行上限 256 字节（不含行尾），超长整行不执行；每回合最多 1,000 行、64 KiB（含行尾），超出部分丢弃并警告。乱码不作为指令执行。缺少结束标记、崩溃和超时由运行器处理，不能靠不断输出非法行免除时限。

### 事件字段草稿

下表是 `EVENT 类型` 后的字段。`U/T/B` 分别表示单位、塔、基地；没有单位 ID 的建筑用 `-1`。同时事件的列表顺序不表示先后关系。

| 类型 | 字段 |
|---|---|
| DAMAGE | `来源方 来源单位id或-1 目标类型 目标方 目标单位id或-1 x y 原始伤害 同步结算后生命` |
| DEATH | `目标类型 所属方 单位id或-1 x y` |
| SPAWN | `id 所属方 W或S x y 生命` |
| BUILD | `x y 所属方 生命` |
| DEPOSIT | `工兵id 所属方 卸货量` |
| INVALID | `阶段号 原回复中的行号 原因码` |

常见原因码包括 BAD_SYNTAX、NOT_OWN_UNIT、DUPLICATE、NOT_ADJACENT、NO_ENERGY、MOVE_CONTESTED、MOVE_BLOCKED、BUILD_CONTESTED。DAMAGE 中的原始伤害可能大于实际扣血；这只是记录口径，不是已冻结的过程分定义。

## 5. 运行限制与计分说明

既定运行要求：bot 单进程，可多线程，所有线程 CPU 用时相加。初始化 CPU 2,000 ms；每回合 CPU 100 ms，超额从每局 3,000 ms 储备扣除，储备为负判超时。墙钟兜底为本回合时限加剩余储备再加 500 ms。时限会按固定单核基准折算，实际值由 LIMIT 发出；BANK 由运行器更新。内存 512 MiB、写文件 16 MiB、打开文件 64 个，另有整局 CPU 硬上限。标准错误本地最多保留 64 KiB，评分时丢弃。

所有 bot 和 C++ 编译都在沙箱内，不联网；评分和校准使用 bubblewrap。plain 只供已有外层沙箱的本地工作区使用。C++ 编译要求 GCC 11、`g++ -O2 -std=gnu++20 -o bot *.cpp`、60 秒上限；Python 要求 3.13，框架只用标准库。bot 编译失败、无 READY、退出或超时判负；双方同回合出错则平局。沙箱准备、资源或框架故障不算 bot 输，需重跑，仍失败的局不计成绩。**当前 bwrap 开发运行器已有对局与故障测试，但速度折算、完整进程树计量和沙箱验收尚未完成；不能用于正式评分。**

正式评分将面对约 12 级固定阶梯，每级 2–3 个不同风格对手，覆盖进攻、经济、控制。L0–L2 公开；更高阶梯仅公开大致风格，不公开实现。每局得分为 `0.75×胜负分 + 0.25×过程分`，胜负分为胜 1、平 0.5、负 0；逐对手、逐级平均，最后各级等权平均。过程分指标及权重还需要 B/C 阶段数据验证和用户确认，当前引擎不计算评分。

## 6. 工具交付状态

在 WSL 工作区用 `.venv/bin/python tools/run_tests.py` 跑开发测试。解释器须为 Python 3.13；运行器测试的 bot 和 C++ 编译都在 bwrap 内执行，不允许裸跑或自动回退 plain。

已提供 Python/C++ SDK 及 `example/`，只用标准库。以下命令使用测试地图打通一局，并验证、查看回放：

```sh
.venv/bin/python -m arena match --a sdk/python/example --b sdk/cpp/example --map tests/fixtures/smoke.map
.venv/bin/python -m arena replay verify <回放路径>
.venv/bin/python -m arena replay show <回放路径> --turn 25
.venv/bin/python -m arena replay summary <回放路径>
```

`match` 默认把所有尝试、结果和回放留在 `runs/matches/`，可加 `--show-stderr` 查看 stderr。测试地图不是验收地图，速度系数尚未标定。详细用法和限制见 `docs/RUNTIME.md`。`check`、`tournament`、`mapgen` 和正式任务包尚未交付。
