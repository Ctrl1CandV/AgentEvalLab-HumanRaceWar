# 前哨：规则与协议

规则集：`standard-1`（2026-11-08 A阶段交审配置）；引擎：`0.1.0-dev`；协议：HRW 1。

已提供引擎、沙箱运行器、SDK、match、回放、地图、bench、check与tournament。A阶段交付等待审查；对手阶梯及正式任务包尚未交付。全部规则参数见 `standard-1.json`，实际对局以初始化PARAM为准。

## 1. 棋盘与目标

两人完全信息、同时行动。地图宽、高各为 24–40，关于中心旋转 180° 对称，两座基地互为对称点。坐标 `(x,y)` 从左上角 `(0,0)` 开始，向右、向下递增。距离统一为 `|dx| + |dy|`，相邻只包括上下左右。

| 地形 | 含义 | 单位能否进入 |
|---|---|---|
| `.` | 空地 | 能，最终每格至多一个单位 |
| `#` | 墙 | 不能 |
| `O` | 矿 | 不能，采完仍是矿格 |
| `S` | 塔基 | 不能，建塔后也不能 |
| `0`、`1` | 两方基地 | 不能 |

攻击阶段一方基地被摧毁，该方立即输；双方同回合被摧毁则平局。否则第 300 回合结算完后依次比较：塔累计分、累计卸货量、基地生命。前一项相同才比较下一项，全部相同则平局。基地生命不回复。单位死亡后携带的矿消失，不能拾取。

## 2. 实体和全部规则参数

| 实体 | 造价 | 生命上限 | 相邻攻击伤害 |
|---|---:|---:|---:|
| 工兵 W | 40 | 60 | 10 |
| 战士 S | 80 | 100 | 20 |
| 基地 | — | 600 | 使用 FIRE，伤害 10、射程 2 |
| 塔 | 150 | 300 | 无攻击 |

工兵每回合最多采 10，最多携带 60；只有工兵能采矿、卸货和建塔。塔建在空塔基上，每回合贡献 1 分，同时是卸货点。塔被摧毁后留下空塔基，不能占领敌塔。

每方开局基地满血、能量 500、4 个满血工兵，初始站位两方对称。工兵和战士合计至多 40。基地每回合最多生产一个单位，生产位置距基地不超过 2；距己方基地不超过 2 的己方单位，每回合回复 5 生命，不超过上限。

协议会发送下列全部参数，bot 应读取而非把数值写死：

```text
TURNS 300              START_ENERGY 500       START_WORKERS 4
POP_CAP 40             BASE_HP 600            BASE_FIRE_DMG 10
BASE_FIRE_RANGE 2      SPAWN_RANGE 2          REGEN_HP 5
REGEN_RANGE 2          WORKER_COST 40         WORKER_HP 60
WORKER_DMG 10          MINE_RATE 10           CARRY_MAX 60
SOLDIER_COST 80        SOLDIER_HP 100         SOLDIER_DMG 20
TOWER_COST 150         TOWER_HP 300           TOWER_POINTS 1
```

单位 ID 全局唯一、不复用。当前分配方式为各方独立序号乘玩家数再加玩家号；同一方内部按 ID 排建造先后。初始位置先选离基地最近的空地，同距采用双方互为旋转的局部排序。bot 以 `UNIT` 消息中的实际 ID 和坐标为准。

## 3. 指令与结算

每个单位每回合最多一条指令；基地可各发一条 SPAWN 和 FIRE。未收到指令的单位原地不动，没有自动攻击或自动射击。

| 指令 | 回合开始时必须满足 |
|---|---|
| `MOVE id N/E/S/W` | 己方存活单位，方向为北/东/南/西之一；目的格能否进入在移动阶段判断 |
| `ATTACK id x y` | 目标为相邻敌方单位、塔或基地 |
| `MINE id x y` | 工兵与有余矿的矿格相邻，携带量未满 |
| `BUILD id x y` | 工兵与空塔基相邻；能量到建造阶段才检查 |
| `SPAWN W/S x y` | 位置是无人占据的空地、距己方基地至多 2，人口未满、能量足够 |
| `FIRE x y` | 目标为距己方基地至多 2 的敌方单位，不能射塔或基地 |

先用共同的回合开始局面校验，再按下列顺序结算。除明确规定的同方建造顺序外，同一步内同时生效。

1. **校验**：非法行只记警告，不判负。第一条语法完整、指向己方存活单位的指令占用该单位槽，即使目标不合法也不能用后一条补上；语法错误的行不占槽。基地两个槽分别处理。
2. **攻击**：ATTACK、FIRE 按回合开始的位置命中；即使目标准备移动也会先受伤。所有伤害同时生效，死亡单位的攻击仍生效，其他动作取消。移除死亡单位和塔；若基地死亡，立即结束，不再生产、卸货、回复或计分。
3. **生产**：成功才扣款；双方在同一格生产都失败且不扣款。开始时已被占用的位置，即使占据者在攻击阶段死亡，也不能用于这次生产。开始时人口已满，不能利用本回合阵亡腾出的人口。
4. **移动**：先拒绝非空地或越界的目的格；再使所有争同一目的格的移动失败；再使直接互换位置的两个单位失败。反复使“目标格仍有不动单位”的移动失败，直到不再变化。其余全部成功，允许三个以上单位的轮转。新生产的单位已占格，算不动单位。
5. **采矿**：每个存活工兵的需求 `q=min(10,60-携带量)`。同一矿格总需求不超过储量时各得 q；否则各得 `min(q,储量//人数)`，剩余全部作废，矿量归零，不重新分配零头或受携带上限限制的份额。
6. **卸货**：与己方基地或现存己方塔相邻的工兵自动卸下全部携带量，增加能量和累计卸货量。同一工兵即使邻接多个卸货点，也只卸一次。
7. **建造**：允许用刚卸货的能量。双方争同一塔基都失败、不扣款，冲突判断先于支付能力。己方多个存活工兵争同一塔基，ID 最小者执行；同方其他塔基的建造也按工兵 ID 递增扣款，缺钱的失败。新塔本回合尚不能接收卸货。
8. **回复**：按移动后的坐标回复己方基地附近的存活单位；不会救活已死亡单位，塔不会回复。
9. **计分**：每座现存己方塔加 1 分，包括本回合新建的塔。然后检查回合上限。

移动受阻、建造争抢或缺钱等不导致判负，通过 INVALID 事件告知本方。输入警告与执行失败分别统计，不改变结算或胜负。

## 4. bot 协议

每局启动一个长期运行进程，通过标准输入和标准输出交换 UTF-8 文本行，行尾为 `\n`。每条消息以 `END` 结束。回复 `END` 后继续运行也计 CPU 用时，计入下一回合。标准输出只写协议，调试信息写标准错误。bot 可以跳过不认识的输入关键字，以兼容以后新增字段。

### 初始化

```text
HRW 1
RULESET standard-1
YOU 0
SEED 8273645512
PARAM TURNS 300
PARAM START_ENERGY 500
...其余全部参数，每行 PARAM 名称 数值...
LIMIT TURN_CPU_MS 100
LIMIT INIT_CPU_MS 2000
LIMIT BANK_MS 3000
MAP 32 32
...32 行地图，每行 32 个字符...
ORE 5 7 400
...全部矿格和初始储量...
END
```

省略号是说明，不是实际协议行。初始化时限内回复 `READY` 并刷新输出。SEED 是提供给本方 bot 的随机种子，引擎结算不使用随机数。

### 每回合观察

首次为 `TURN 1`。双方的能量、单位、建筑和矿量都可见。

```text
TURN 17
PLAYER 0 <能量> <塔累计分> <基地生命> <累计卸货量>
PLAYER 1 <能量> <塔累计分> <基地生命> <累计卸货量>
UNIT <id> <所属方> <W或S> <x> <y> <生命> <携带量>
TOWER <x> <y> <所属方> <生命>
ORE <x> <y> <余量>
EVENT <类型> <字段...>
BANK <剩余储备毫秒>
END
```

每个存活单位、塔各一行，矿只列余量大于 0 的格子。事件来自上一回合；本方 INVALID 只发给本方。回复零条或多条指令，最后写 `END` 并刷新输出，例如：

```text
MOVE 12 N
MINE 3 6 7
SPAWN S 4 5
END
```

### 容错

逐行校验。未知指令、字段错误、不存在或非己方的单位、不满足条件的操作，只作废对应行。允许空行、首尾空白、制表符和 CRLF。单行上限 256 字节（不含行尾），超长整行不执行；每回合最多 1,000 行、64 KiB（含行尾），超出部分丢弃并警告。乱码不作为指令执行。缺少结束标记、崩溃和超时由运行器处理，不能靠不断输出非法行免除时限。

### 事件字段草稿

下表是 `EVENT 类型` 后的字段。`U/T/B` 分别表示单位、塔、基地；没有单位 ID 的建筑用 `-1`。同时事件的列表顺序不表示先后关系。

| 类型 | 字段 |
|---|---|
| DAMAGE | `来源方 来源单位id或-1 目标类型 目标方 目标单位id或-1 x y 原始伤害 同步结算后生命` |
| DEATH | `目标类型 所属方 单位id或-1 x y` |
| SPAWN | `id 所属方 W或S x y 生命` |
| BUILD | `x y 所属方 生命` |
| DEPOSIT | `工兵id 所属方 卸货量` |
| INVALID | `阶段号 原回复中的行号 原因码` |

全部 INVALID 原因码：`ACTOR_DEAD`、`BAD_COMMAND`、`BAD_DIRECTION`、`BAD_SYNTAX`、`BAD_TEXT`、`BAD_UNIT_TYPE`、`BAD_UTF8`、`BUILD_CONTESTED`、`BUILD_REDUNDANT`、`CANNOT_BUILD`、`CANNOT_MINE`、`CARRY_FULL`、`DUPLICATE`、`LINE_TOO_LONG`、`MOVE_BLOCKED`、`MOVE_CONTESTED`、`MOVE_NOT_GROUND`、`MOVE_SWAP`、`NOT_ADJACENT`、`NOT_EMPTY_GROUND`、`NOT_EMPTY_SITE`、`NOT_ENEMY_TARGET`、`NOT_ENEMY_UNIT`、`NOT_OWN_UNIT`、`NO_ENERGY`、`NO_ORE`、`OUT_OF_RANGE`、`POP_CAP`、`SPAWN_CONTESTED`、`TOO_MANY_BYTES`、`TOO_MANY_LINES`。DAMAGE 的原始伤害可能大于实际扣血；各攻击来源记录同一轮同步结算后的生命，不应当作依次扣血。

## 5. 提交格式、运行限制与评分概述

提交是一个目录：Python 入口为 `main.py`；C++ 为顶层一个或多个 `*.cpp`。两种入口只能选一种。不得含符号链接（包括提交目录本身）或特殊文件；单文件至多 16 MiB，总量至多 64 MiB。`__pycache__` 不进入源码快照。无入口、两种入口都有、链接或超大小均按提交编译失败判负，并保存明确原因；`check` 使用同一校验。

bot 强制单进程，不能 fork/vfork 或改变绑核；可开线程，沙箱任务总上限为 16（含主线程和沙箱管理进程，因此 bot 可创建的工作线程可能少于 15）。所有线程 CPU 用时相加，包括已退出线程；不能用创建短命线程规避计时。初始化 CPU 2,000 ms；每回合 CPU 100 ms，超额从每局 3,000 ms 储备扣除，储备为负判超时。每回合用时是本次 END 与上次 END 的累计 CPU 之差，第一回合从 READY 算起。墙钟兜底为本回合时限加剩余储备再加 500 ms。

按实际并行度运行的固定基准将折算时限、储备、墙钟余量和整局 CPU 硬上限，实际值由 LIMIT 发出；BANK 由运行器更新。已提供 `bench --jobs N`；独立对局可用 `match --timing <jobs=1的bench结果>` 按测得的系数与CPU运行。不提供校准时仍使用明确标记的未折算开发时限；`tournament` 会按相同并行度和CPU池测量并折算，但仍不能据此宣称正式评分验收完成。

运行时地址空间 512 MiB，单文件上限 16 MiB，打开文件至多 64 个，禁用 core dump。**运行时合成根目录 `/`、`/tmp` 和 `/dev` 文件系统只读，不支持写临时文件或共享内存文件；标准输入输出和设备读写不因此禁用。** 这是当前实现选择，不承诺可写 64 MiB 临时空间；本地 plain 工具也须告知相同评分限制。运行时禁止新进程/命名空间、修改绑核、ptrace/跨进程内存访问及内存文件、SysV IPC和POSIX消息队列分配。普通线程、锁和条件变量仍可用。标准错误本地最多保留 64 KiB，评分时丢弃。

所有 bot 和 C++ 编译都在沙箱内，不联网；评分和校准使用 bubblewrap。plain 只供已有外层沙箱的本地工作区使用。C++ 编译要求 GCC 11、`g++ -O2 -std=gnu++20 -I/sdk -o bot *.cpp`、墙钟及CPU均有60秒上限、每进程地址空间2 GiB、任务数上限16、单文件64 MiB；编译串行执行，编译临时文件使用本方磁盘构建目录，不使用无总量限制的 RAM tmpfs。Python 要求 3.13，框架只用标准库。bot 编译失败、无 READY、启动标记后以任何退出码退出或超时判负；双方同回合出错则平局。运行器未收到可信启动标记的沙箱准备失败、机器资源或框架故障不算 bot 输，最多重试三次并保留所有记录；隐藏对手或地图配置错误不能算提交方输。**真实bwrap回归、批量折算与全局CPU租约已验证；正式评分仍需后续阶段交付和审查。**

评分看对固定阶梯的对局表现，胜负最重要，细节不公开。约 12 级，每级 2–3 个不同风格对手，覆盖进攻、经济、控制：L0–L2 为公开的简单策略；L3–L5 有任务分配和局部估计；L6–L9 会搜索、调整打法和选路线；L10–L11 为长期开发和调参的强对手。模型应尽力赢，不需要知道内部评分细节。

## 6. 工具交付状态

在 WSL 工作区用 `.venv/bin/python tools/run_tests.py` 跑开发测试。解释器须为 Python 3.13；运行器测试的 bot 和 C++ 编译都在 bwrap 内执行（plain 路径也有明确的外层 bwrap），不允许裸跑或自动回退 plain。

已提供 Python/C++ SDK 及 `example/`，只用标准库。以下命令使用测试地图打通一局，并验证、查看回放：

```sh
.venv/bin/python -m arena match --a sdk/python/example --b sdk/cpp/example --map tests/fixtures/smoke.map
.venv/bin/python -m arena replay verify <回放路径>
.venv/bin/python -m arena replay show <回放路径> --turn 25
.venv/bin/python -m arena replay summary <回放路径>
```

`match` 默认把所有尝试、结果和回放留在 `runs/matches/`，可加 `--show-stderr` 查看 stderr。测试地图不是验收地图；不提供校准时仍是未折算开发局；使用评测机参考的折算方法见 `docs/TIMING.md`。详细用法和限制见 `docs/RUNTIME.md`。

现有 `maps/public/` 40 张和 `maps/scrimmage/` 4 张，均通过布局检查；平衡检查使用全部40张公开图，不使用练习图补充样本。可用 `.venv/bin/python -m arena mapgen --type corridor --size 32 --seed 7` 生成地图，用 `.venv/bin/python -m arena mapcheck maps/public/corridor-01.map` 检查默认生成配置。种子、摘要和分区口径见 `maps/catalog.json`、`maps/README.md`；布局检查不会对自定义 match 地图新增限制。`check <bot目录>` 和 `tournament --bot <bot目录> --opponents <目录...> --maps <地图目录> --jobs N --out <结果目录>` 已提供，支持 `--resume`；完整用法见 `docs/BATCH.md`。plain 只能显式接入已隔离的本地外层沙箱，不是宿主裸跑开关；8核工作区最多3个并行对局并留runner核，正式评分仍用bwrap。正式任务包尚未交付。
