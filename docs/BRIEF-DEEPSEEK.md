# 任务书：为前哨竞技场编写一条控制风格的强 bot

- **给：** DeepSeek，在用户的开发机上，通过 pi 工作。
- **来自：** AgentEvalLab 评测负责人。
- **日期：** 2026-11-09。

## 用户启动时发给你的话（用户复制使用）

> 你是前哨竞技场的阶梯 bot 作者，按 `BRIEF-DEEPSEEK.md` 工作。先读它、`rules.md`、你自己的 `NOTES.md`（第一轮还没有），以及 `handoff/in/` 里最新的反馈；然后做这一轮的开发，交付到 `handoff/out/`，写好 `NOTES.md`，停下来。

---

## 1. 背景

前哨是一个两人同时行动的格子即时战略游戏，规则全文在 `rules.md`。这个项目要建一条由强到弱的对手阶梯，用来评测 AI 模型写 bot 的能力。阶梯的高层需要几种风格不同的强 bot。

你负责其中一条：**控制风格**，打法以抢塔、守点、骚扰为主。另一位作者（astra）负责进攻和经济风格，你们互相看不到对方的代码。这样做，是为了让阶梯不全出自同一个作者之手。

## 2. 目标

写一个尽可能强的控制风格 bot：

- 稳定地大比分赢下工作区里的所有公开 bot，包括 `M-balanced`；
- 在此之上，越强越好。你交付后，评测方会用隐藏的地图和对手组测出它的强度，结果写进反馈；
- 风格要能看出是“控制”：以塔分和地图控制为主要取胜手段，能骚扰对方经济，也能守住要点；
- 输掉时要输得有道理，不能因为故障、超时或协议错误而输。

## 3. 你能用的材料

工作区里只有公开材料：

- `rules.md`：规则和协议全文；
- SDK：`sdk/python/hrw.py`、`sdk/cpp/hrw.hpp`，以及示例 bot；
- arena 工具：`check`、`match`、`tournament`、`replay`，用法见工作区的 `README.md`；
- 公开 bot：`bots/public/` 里的 10 个；
- 地图：`maps/public/` 40 张，`maps/scrimmage/` 4 张。

你可以联网查一般性的算法资料，但 bot 代码必须自己写，只能用 Python 或 C++ 的标准库。

## 4. 规则和限制（和其他所有 bot 一样）

- 单进程，可以开线程（有上限，见 `rules.md`），不能 fork，也不能改绑核。
- 每回合有 CPU 时限，超出部分从时间储备里扣，储备用完判负。时限的实际数值从开局消息的 `LIMIT` 行读取，不要写死。回复 `END` 之后继续计算也算时间。
- 运行时没有可写的文件系统，没有网络。
- 提交是一个目录：Python 的入口是 `main.py`；C++ 是顶层的若干 `*.cpp`，编译命令见 `rules.md`。两种只能选一种。
- 强度要来自算法和离线调好的参数。时限之内可以做搜索或模拟，评测方会按同样的时限运行你的 bot。
- 需要随机性时，用开局消息里的 `SEED`，让结果可以复现。

## 5. 每一轮怎么做

1. 读本任务书、`rules.md`、`NOTES.md` 和最新的 `handoff/in/feedback-r<NN>.md`。
2. 定下这一轮只做一两项改进，先写进 `NOTES.md` 的“本轮计划”。
3. 开发，并在工作区里自测：
   - 每个版本都要先过 `check`；
   - 用 `tournament` 在 public 图上对全部公开 bot 打满、交换座位；
   - 和自己的上一版直接对战。
4. 交付到 `handoff/out/r<NN>/`（`NN` 从 `01` 开始）：
   - `bot/`：完整的 bot 目录；
   - `NOTES.md`：设计思路、关键参数、这一轮改了什么、自测结果（对每个公开 bot 的胜负和得分率，以及对上一版的结果），还有已知的问题；
   - `SHA256SUMS`：`bot/` 里每个文件的 sha256。
5. 停下来，等评测方的反馈。不要自己开始下一轮。

## 6. 不要做的事

- 不要修改 arena、SDK、规则和公开 bot。
- 不要试图读取工作区以外的目录，也不要寻找其他作者的代码。
- 不要推送任何东西，工作区不连 GitHub。
- 不要针对某一张公开地图或某一个公开 bot 写特殊处理。评测用的是你没见过的地图和对手，这类写法只会让 bot 变脆弱。
- 自测结果要如实写，输的局也要写。

## 7. 你会收到的反馈

评测方会在 `handoff/in/feedback-r<NN>.md` 里写：

- 你的 bot 在隐藏地图上对一组固定对手的得分，以及临时 Elo；
- 对每个公开 bot 的胜负；
- 运行故障、超时，如果有的话；
- 和你上一版相比是变强还是变弱，是否被采纳为你的当前版本。

反馈不会包含其他作者的 bot 的实现或弱点。
