## 1. 背景

前哨是两人同时行动的格子即时战略游戏，规则全文见 `rules.md`。这个项目要搭一个由弱到强、大约 12 级的对手阶梯，用来评测 AI 模型写 bot 的能力。

阶梯上层需要几种风格的强 bot：

- **进攻：** 早压制，逼对方交战；
- **经济：** 扩张，后期大军；
- **控制：** 抢塔、守点、骚扰。

另一位作者写的现有 bot，最强的比公开的 `M-balanced` 高约 250 Elo，大约能赢它八成的局。阶梯顶端需要比 `M-balanced` 高约 600 到 900 Elo 以上。高约 600 Elo，大约相当于对它赢九成七。

现在由你负责写强 bot。你看不到其他作者的代码，他们也看不到你的。这样安排是为了让阶梯不全出自同一个作者。

## 2. 目标

1. **第一条主线：** 从三种风格里选一种，写一个尽可能强的 bot，打法要能看出是这种风格。
   - 先在公开对手上接近全胜，包括 `M-balanced`。作为参考，在 40 张 public 图上双座自测，对 `M-balanced` 的得分率应达到 95% 以上。
   - 在此基础上越强越好。评测方会用你没见过的地图和隐藏对手组，测出相对 `M-balanced` 的临时 Elo，结果写进反馈。
2. **以后的工作：** 评测方在反馈里说明后再做，包括第二种风格的强 bot，以及同一条主线按算力分出的几个强度档。现在写 bot 时，就让搜索或模拟的工作量由**一个参数**控制，例如每回合最多评估多少个方案，方便以后分档。
3. **输要输得有道理：** 不能因为崩溃、超时或协议错误而输。

## 4. 规则和限制（与其他所有 bot 相同）

- **进程与线程：** 单进程，可以开线程，上限见 `rules.md`；不能 fork，也不能改绑核。
- **运行环境：** 运行时没有网络，也没有可写的文件系统。
- **CPU 时限：**
  - 每回合的用时，是这一次 `END` 与上一次 `END` 之间整个进程的 CPU，包括所有线程、上一回合 `END` 之后还在做的计算，以及读取和解析本回合输入。第一回合从 `READY` 算起。
  - 超出每回合时限的部分从储备里扣，储备扣完判负。
  - 实际数值从开局消息的 `LIMIT` 行读取，不要写死。本机评测大约是每回合 60 ms、初始化 1200 ms、储备 1800 ms。
- **提交格式：** 提交是一个目录。Python 的入口是 `main.py`；C++ 是顶层的若干 `*.cpp`，编译命令见 `rules.md`。两种只能选一种。
- **随机性：** 需要随机时，用开局消息里的 `SEED`，让结果可以复现。
- **强度来源：** 强度要来自算法和离线调好的参数。在时限之内做搜索或模拟是可以的。

## 5. 之前开发中得到的几条经验（不涉及任何人的代码）

1. **调参的目标要对。** 以前对一组固定的、已经能赢的对手调参，总分提高了，和自己上一版直接对战却输了。请把"对自己当前最好版本的直接对战"（双座、多图）作为主要信号，公开 bot 只作回归检查。
2. **修好一个具体问题，不等于变强。** 每个改动都要用对局验证。
3. **按工作量控制思考，不要按时钟。** 最好用固定的工作量上限（节点数、评估次数），在 jobs6 的并行自测下，确认每回合 CPU 的**最大值**离上限有足够余量。以前按 CPU 份额切档时，单个回合偶尔比平时慢好几毫秒，最容易出问题的是第一回合、后期大局面和并行负载。按工作量控制，结果还可以复现。
4. **模拟要和引擎一致。** 写了规则模型或模拟器，就用 arena 的引擎或 `replay` 核对，免得在错误的模型上搜索。
5. **调参和自对弈用 CPU 跑**，不需要调用模型。

## 6. 每一轮怎么做

1. 读本任务书、`rules.md`、你的 `NOTES.md`，以及最新的 `handoff/in/feedback-r<NN>.md`。
2. 在 `NOTES.md` 写下"本轮计划"。
3. 开发并自测：
   - 每个版本先过 `check`；
   - 用 `tournament` 在 40 张 public 图上，对全部公开 bot 双座打满；
   - 和你上一次交付的版本直接对战；它保存在 `handoff/out/r<NN-1>/` 里。
4. 交付到 `handoff/out/r<NN>/`，`NN` 从 `01` 开始：
   - `bot/`：完整的 bot 目录。如果这一轮交了不止一个 bot，改用 `bots/<名字>/`，最多 3 个，每个都注明风格。
   - `NOTES.md`：
     - 设计思路、关键参数，以及这一轮改了什么；
     - 自测结果：对每个公开 bot 和对上一版的胜负与得分率，输的局也要写；
     - 自测中见到的每回合 CPU 最大值；
     - 这一轮自测和调参一共打了多少局；
     - 会话的起止时间、模型名称；
     - 已知问题。
   - `SHA256SUMS`：交付目录里每个文件的 sha256。
5. 停下来，等评测方的反馈。不要自己开始下一轮。

**每一轮的限制：**

- 一轮只用一个会话，墙钟不超过 8 小时；
- 自测和调参合计不超过 30000 局；
- 并行不超过 jobs6，只用提供的两份预算锁；
- 不改 `TMPDIR` 和 CPU 锁目录。CPU 被占用时，就等待或停下，不要抢锁。
