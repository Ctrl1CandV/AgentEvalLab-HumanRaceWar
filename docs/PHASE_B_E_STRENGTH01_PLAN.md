不用旧pair-major日程。新提案按原地图顺序分40块，每块58局：先两局基线自对弈，再按七对照及双座遍历；每个四档小组用`(地图序号＋对照序号＋座位) mod 4`循环移位。每档在四个发起顺位各出现140次，减少档位与运行时段完全重合。固定jobs6；块内按登记顺序派发，上一地图块全部收束才开下一块。完成顺序不保证相同，也不声称已消除温度、调度或机器时段影响。

主要比较是100%减10%的总体胜负得分率。每局半分取胜2、平1、负0；每档560局，每个地图簇保留全部七对手×双座14格。以**40个地图簇**而非560局为重采样单位：`random.Random(4219)`，每次依次调用40次`randrange(40)`，共4000次有放回抽样，排序索引99/3899给95%区间；半分差除以1120换成得分率差。不得丢抽样、改seed或追加至显著。

这是熟悉public上的有界工程筛选，不是独立留出或正式显著性结论；n=1执行轮次，簇区间不覆盖运行间波动、开发选型和重复使用地图造成的偏差。没有未经验证的功效保证。除主要比较外，四档总分、对保留版直接战、六池总分和结束方式完整报告；其他切片仅描述，不择优代替全体。

## 4. 拟沿用的工程门（不修改B正式验收）

必须同时满足：

1. 全部预定记录/身份/预算齐全，新局完整回放验证通过；零bot故障、超时和协议警告，零基础设施错误。运行期合法冲突/无效动作仍按既有计数口径另报，不混作协议警告。
2. 四档总半分满足`H10≤H25≤H50≤H100`，且100%−10%的地图簇区间下端严格大于0。
3. 100%直接对E-r02至少44分/80局（半分≥88）；对原六池480局总得分相对旧版下降不超过2pp，即`(oldHalf−newHalf)×100≤1920`。

所有门通过，只支持请求下一轮单独登记的dev取舍，不在本轮采纳；反复使用的dev不称独立留出。若日后批准dev，原40/80图两段门及55%/2pp要求仍适用，但局数和授权必须另记。
