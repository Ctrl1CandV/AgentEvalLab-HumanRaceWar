# A1 实现说明与待确认项

更新：2026-11-07。当前只完成游戏引擎与内存中的消息解析，不是 A 阶段报告，也没有冻结 `standard-1`。规则参数全部保持 DESIGN 附录 A 的默认值。开发主工作区和环境已经迁入 WSL，见 `docs/WSL_HANDOFF.md`。

## 代码边界

- `arena/core/game.py`：与游戏无关的接口、事件、警告、结果结构；玩家参数使用列表，不把运行器接口限定成两人。
- `arena/games/outpost/`：前哨 v1 的两人地图读取、状态、规则、指令校验、九步结算、消息、哈希和 ASCII 棋盘。这里不启动进程，不访问网络或时钟，不使用随机数。
- `tests/`：可信引擎的例子测试、输入模糊测试、确定性和对称性测试，不是 bot 程序。测试使用人工构造的局面；地图 fixture 只满足结构检查，不是通过 DESIGN 7.2 验收的公开地图。
- `tools/run_tests.py`：标准库测试入口。记录测试进程 CPU 时间，不把它当作引擎或运行器性能数据。

`new_match(map_text, ruleset, seeds)` 的 `ruleset` 是参数名到整数的覆盖字典；`{}` 使用全部默认值。`parse_orders` 不修改状态；`step` 只接受当前回合、对应玩家的解析结果。调用者错用结构化接口会收到 `ValueError`，bot 的非法文本只会产生警告。

状态中的 `turn` 是已结算回合数，开局为 0；首次观察发 `TURN 1`。哈希包含完整规则局面、种子、分配编号的计数器、事件和结果，不含运行器负责的 `BANK`。同一组指令不应因计时差异而改变规则哈希。运行器尚未实现。

## 按 BRIEF 3.3 暂定的细节

以下处理均公开、对两方对称；需要审查确认后才能随 A 阶段冻结。对应测试见 `tests/COVERAGE.md`。

| 编号 | 设计尚未给出完整细节的地方 | 当前实现 |
|---|---|---|
| I01 | 开局工兵的具体站位和单位编号 | 在出兵范围内选最近的空地。距离相同时按基地的局部坐标排序：位于地图前半的基地按北、西优先，另一侧取旋转后的顺序。以 `(y,x)` 和旋转坐标的字典序确定方向，不用玩家编号。每方有独立递增序号，单位 ID 为 `序号 × 玩家数 + 玩家号`，从 0 开始且不复用。 |
| I02 | SPAWN 的“空地”是否允许已有单位 | 必须在回合开始时既是 `.` 又无人占据；即使占据者稍后移动或被击杀，也不能在该回合生产到那里。人口和能量也按回合开始检查。MOVE 只要求目的地地形为 `.`，占用关系留到移动阶段处理。 |
| I03 | 第一条指令非法后，第二条能否补上 | 第一条语法完整、指向己方存活单位的指令占用单位槽，即使它不满足邻接等条件；之后同单位的指令都记重复。语法不完整的行不占槽。基地的生产、射击分别采用同样处理。 |
| I04 | BUILD 冲突与支付能力的关系 | BUILD 的开始条件不检查能量，以允许使用本回合卸货所得。双方争同一塔基先判双方失败，即使其中一方没有钱。死亡工兵的 BUILD 先取消，再在存活工兵中按 ID 选执行者和扣款顺序。这是对 4.3、4.4 原文的直接实现。 |
| I05 | 过量伤害如何记录 | 生命下限记录为 0；每次攻击记录原始伤害及共同结算后的目标生命。`damage_dealt` 暂记原始伤害，包含过量部分。事件可结合前一状态重算实际扣血。没有实现过程分，也没有决定 C 阶段采用哪种伤害口径。 |
| I06 | 合法但未执行成功的指令如何反馈 | 移动冲突、被新单位挡住、建造时缺钱等，和格式错误一样通过仅本方可见的 INVALID 反馈，并计入警告总数；不因此判负或扣分。INVALID 含结算阶段，能区分输入无效与执行失败。 |
| I07 | 同一步内事件的排序 | 事件是同时发生的事实，不按列表顺序再次结算。存档按阶段、类型、接收方、字段排序以保证稳定。对称测试旋转坐标、交换玩家和 ID 后重新排序比较全部事件，保留重复事件及次数，不只比较事件种类。 |
| I08 | `.map` 文件格式 | 使用协议已有的 `MAP W H`、H 行地形、全部 `ORE x y amount`、`END` 记录。校验尺寸、符号、基地、中心对称和矿量对称；连通性、资源布局等验收留给地图生成器。此格式不是新增 bot 消息。 |

## 输入与事件

协议头和指令格式保持 DESIGN 第 5 节不变。具体事件字段按 5.5 的授权先写成草稿，见 `rules/rules.md`；尚无发布后的兼容负担。

解析器允许空行、首尾空白、制表符和 CRLF。超出 256 字节的整行不执行；一回合超出 1,000 行或 64 KiB 后不再接受剩余行。合法 `END` 结束当前输入。缺少 `END`、原始字节流的分帧、持续洪泛输出及进程退出，需要运行器处理，**目前未完成**。当前乱码测试只验证送入解析器的字符串，不等于完成真实管道健壮性验收。

`DAMAGE` 按每个攻击源记录，多个来源攻击同一目标时，各记录的 `hp` 都是这一攻击阶段同时扣血后的生命；不能把这些记录当作依次扣血的指令。
