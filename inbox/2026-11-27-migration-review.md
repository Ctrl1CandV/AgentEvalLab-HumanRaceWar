# 评测机迁移复核（CA，2026-11-27）

## 结论

在评测机上按 `MIGRATION.md` 执行七步，全部通过，结果和开发机逐局一致。**HRW 1.0.0 可以作为第一版在这台评测机上使用，接入 AgentEvalLab。**

使用的附加条件：**正式评分必须在安静的机器上运行**，由 AgentEvalLab 的评分包装保证（见第四节）。原因是 CA 另加的重负载 bot 检查：一个把限时用到约 80% 的提交，在迁移说明规定的六进程负载下有 76 局超时；在安静机器上，即使把限时用满，也是 0 超时，结果逐位精确。这个问题不需要 HRW 发新版。

## 三、CA 另加的检查：计算偏重的提交

**为什么要加。** 迁移说明的噪声测试用"最重的阶梯成员"E-r02，但它每回合只用约 0.6 ms CPU，约为限时的 1%，测不出提交计算偏重时的情形。被测模型可能写出把限时用到七八成的 bot。

**构造。** 把公开的 M-balanced 复制一份，每回合出完指令后，再做一段固定工作量的纯计算。这段计算不影响策略，所以只要不超时，每局结局必须和 M-balanced 完全相同。比较方法：评分时，每局的对手、地图槽位和座位都和 M-balanced 的评分对上，逐局比较完整结果，并从回放中只取本方的 CPU 时间和储备余量。

- **H100：** 每回合 4,900 万次循环。用 `arena check` 单独标定时约 68 ms，但在 6 局并行的正式评分中实测约 85 ms，正好是限时。
- **H80：** 每回合 3,940 万次循环，按正式评分条件标定为约 68 ms，即限时的 80%。

| 评分 | 每回合 CPU 平均 / p99 / 最大 (ms) | 超过 85 ms 的回合 | 超时局 | 结局和 M-balanced 不同的局 | headline | 胜负主分 |
|---|---|---|---|---|---|---|
| H100 空闲 | 84.6 / 98.2 / 220 | 39% | 0 | 0 | 0.482884（相同） | 0.452381（相同） |
| H100 负载 | 99.7 / 121 / 326 | 99.7% | 333 | 333 | 0.072991 | 0.065934 |
| H80 负载 | 81.9 / 132 / 995 | 21% | 76 | 76 | 0.458999 | 0.443223 |

负载使用 `tools.release_noise` 的六个 CPU 忙循环，和第 5 步相同。

H80 的空闲评分没有单独打。它的计算量比 H100 少，而 H100 空闲时已经是 0 超时、逐局相同，H80 空闲必然也一样。

**读法：**

1. **安静机器上精确。** 即使平均用满限时，储备也吸收了所有超出部分，结果逐位精确。
2. **负载让同样的计算多花约 18–20% 的 CPU 时间。** H100 从 84.6 ms 升到 99.7 ms；H80 按计算量折算约 68 ms，实测 81.9 ms。原因有两个：一是负载进程没有绑核，会落到 bot 所在物理核的另一个超线程上；二是全核满载时睿频下降。最大值 995 ms 这类尖峰，多半是 WSL2 的宿主机抢走了虚拟 CPU。
3. **0.03 的主分容差会掩盖这类变化。** H80 负载下有 76 局超时，headline 却只差 −0.024，胜负主分只差 −0.009，按迁移门槛算"通过"。所以噪声检查不能只看主分差，还要看超时和故障局数。
4. **两把锁的折算一致。** 同一份计算量，在 jobs1 自测条件下约占限时 107%（67.5 / 63 ms），在 jobs6 正式评分中占 99.5%（84.6 / 85 ms）。两者相差约 7%，而且正式评分一侧更宽松，所以模型在工作区自测不超时的 bot，正式评分时不会因为折算而意外超时。

原件只存在本机 `~/projects/HRW-1.0.0/private/ca-checks/`，不上传。

## 四、对 AgentEvalLab 接入的要求

1. **CA 独占运行。** 正式评分期间不跑其他测评题族。
2. **评分前后各测一次速。** 用 `arena bench --jobs 6`，和本机 jobs6 锁的速度系数对比，任一次超出容差，这次评分就标为无效，不出分数，等机器安静后重评。两次测速的结果、提交每回合的 CPU 分布和超时数，都写进评分记录。
3. **用户侧。** 评分期间，这台笔记本的 Windows 一侧和 WSL 一侧都不跑重活。
4. **锁目录不和任务工作区共享。** AgentEvalLab 在所有会话结束后才评分，CA 又独占运行，模型的本地自测不会和正式评分同时发生；不共享还能避免模型占住锁。这和 `MIGRATION.md` 开头"任务工作区的本地测试命令也须共用 `HRW_LOCK_DIR`"不同，按偏差记录。
