# 公开策略动物园

A阶段的10种SDK策略。v15在standard-1上通过完整D6数值条件，等待阶段审查；不是已经校准的阶梯。每个 `public/<代号>/` 都可独立提交，包含 `main.cpp` 和相同的公开 `strategy.hpp`，只依赖C++标准库与 `hrw.hpp`。生成入口是 `tools/generate_zoo.py`，模板在 `tools/zoo_strategy.hpp`；默认拒绝覆盖不同源码。摘要见 `catalog.json`。

| 代号 | 具体做法 |
|---|---|
| Z-idle | 只READY/END，不发游戏指令 |
| Z-random | 随机选择当前观测中合法的移动/攻击/采矿/建造/出兵/射击；同时执行仍可能失败 |
| Z-miner | 初始工兵采矿/卸货，不生产或建塔 |
| Z-rush | 初始工兵供给，所有生产用于战士，直接攻基地 |
| Z-wrush | 初始及新工兵全部速攻，不经营后续经济 |
| Z-eco | 先扩张至18工兵或达到开兵时刻，再生产战士推进；不建塔 |
| Z-turtle | 7工兵只采家门矿，其余人口为守家战士 |
| Z-towers | 多工兵、少量固定矿工，其余占塔；不出战士 |
| Z-harass | 6工兵供给、至多10战士，优先工兵和远离基地的塔 |
| M-balanced | 经济/两名建造者/4塔目标/战士；参考敌军数量调整生产，保留少量守兵，附近出现敌军时回防 |

有意图的策略均可用基地FIRE自卫。共同基础仅含一层局部集火、静态地形距离、带占用/预留格的BFS移动，以及短暂停滞后的让路，不做搜索、不读取对手代号或地图文件名。采矿优先较短往返路线，运输到最近基地/己塔；坐标打破平局使用基地的旋转局部坐标。

v5修复资金与交通：仅12步回防范围内的敌军可取消M的建塔预留；占格BFS找不到完整通路时，用地形距离继续接近（下一格仍检查占用）；两次实际移动失败后允许种子派生的短暂停让，避免双方永久争同一格。不改变各策略配置或游戏规则。v3/v4/v5练习矩阵分别保留，v5仍未达平衡条件。

v6只调整M的开局优先级：既有最低军力目标 `min(3, 敌方战士数+1)` 未满足时，暂不派建造者或留塔钱；达标后继续保留塔预算，远敌不能无限挤占。其余九种打法不变。这修正了“生产想补兵、建造预留却阻止补兵”的冲突，真实bwrap最小反例修前失败、修后通过；尚不能据此宣称平衡通过。v5源码保留在Git及P1/P2冻结批次中。

v7继续修M的可见兵力分配：兵力落后时先保留一处前哨，再补足与敌方相当的战士；至少6工兵的经济已建立后，补兵优先于额外工兵和更多塔。少于6工兵仍可恢复经济。无搜索、局部模拟或对手识别。两个独立决策反例先失败后通过，完整矩阵结论另报。

v8修M的全军回防：只有距入侵者12步以内的部队参与拦截，远征军不因后方出现一个敌人就全部折返；原有驻守兵和附近增援继续防守。最小真实bwrap反例修前失败、修后通过；完整矩阵单独报告。

v9补上v8过窄的回防范围：中场部队在后方威胁比敌基地更近时也会拦截，已经接近敌基地的远征军仍不折返。出征后若敌方塔更多，主目标改为基地，不无限绕路清塔；塔数不落后时保留就近拆塔。仅比较公开数量与步行距离，12项策略回归通过，平衡效果另测。

v10独立检验纯经济打法的固定投入目标：Z-eco由24工兵改为12，仍先招工、再出军队、不建塔，不读取敌军数量或对手代号，也没有加入搜索。P4全部80局开局显示24工兵的投入先造成军力缺口；本候选检验减轻过度投入能否让经济路线形成军队。骚扰及其余打法不改。新决策测试只确认12工兵时转为出兵，不表示旧配置违反协议；是否改善平衡、是否产生新的通吃者，均以独立完整矩阵为准。

v11把M对战士和工兵的回防触发分开：战士沿用12步范围，工兵只有进入基地射程外一格以内才触发主力拦截，避免采矿工兵反复召回全军。基地附近的工兵速攻仍会被拦截；15项定点测试通过，实际胜率另验。

v12将Z-eco的固定目标从12回调至16：v10/P7完整矩阵中，12工兵路线对骚扰和速攻均50/80，自己成了新的通吃者，因此不采纳。16仍是不看对手的固定先经济后军队路线。配置测试改为核对目录中声明的目标上下界，不把某个试验常量当协议要求。v11的M与16工兵配置合成v12跑独立完整矩阵；M自对弈及不含E的配对只受M变化，其他单一打法对E只受E变化，M对E不能分拆归因。

v13补上终结与入口清理：出征中的战士贴到敌基地后优先攻击基地；若附近4步内有明显更近的敌方阻挡单位，先清理该局部目标，避免全军只挤一个入口。沿用现有BFS，没有改寻路框架。两个新增决策反例先失败后通过。maze-01两局定向回归虽首次打掉基地240HP，仍双败，不能记为平衡修复成功。

v14把固定经济目标16→18（16对速攻恰为40/80，尚未严格被克制），M的固定出征时刻115→80（仍±8），给迷宫行军与突破更多时间。没有按地图或对手切换常量。17项决策测试通过，但maze-01两局定向回归仍双败；完整v14/P7仍因铺塔maze 10/20失败，未采纳。

v15仅改M：建造工上限2→3；增加后先暴露出按ID抢占目标的旧分配问题，再改为最近工兵/塔基的贪心配对，并按剩余塔目标限制任务数。忙于作战或卸货的工兵不接新建造任务，没有可建塔基时不再空留塔款。两个新增反例及原资金回归先失败后通过，19项策略测试通过。maze-01换边仍双败（分差从295缩到48），全部保留；完整v15/P7的3680局全验证，并首次满足所有数值平衡条件。只报告整轮结果，不以局部改善代替验收。

所有随机量来自协议SEED。M-balanced只对工兵目标作±1、进攻时刻作±8回合变化，算法、每回合工作量和整体打法相同；不以种子切换强弱版本。正式A矩阵使用预先固定的17/29种子，换边时种子跟随各自bot；额外跑M的不同种子自对弈。不能把同图同位置同种子的重复当独立样本。

不要直接执行这些程序或在宿主编译。用 `arena check`、`match`、`tournament` 的bwrap后端；已有明确外层沙箱的本地工作区才可显式选择plain。平衡数据产出后另报告，不根据本说明预设谁应胜出。
